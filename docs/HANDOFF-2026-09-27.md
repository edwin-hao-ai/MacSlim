### 1. 英文截图重抓（必须，混排不能上 ASC）

现有 8 张里**英文 4 张是旧的混排版**，必须用新构建重抓。

**已验证可用的方法**（照抄，踩过的坑都在这）：

```bash
# 切英文：只给这个 app 指定语言，不影响系统
defaults write com.vgoapp.macslim AppleLanguages -array en
osascript -e 'tell application "MacSlim" to quit'; sleep 2
open /Users/edwinhao/.cargo/shared-target/debug/bundle/macos/MacSlim.app; sleep 8
osascript -e 'tell application "System Events" to tell (first process whose name is "macslim") to set position of window 1 to {281, 138}'
sleep 1
D=/Users/edwinhao/VGOAPP/public/downloads/macslim
cliclick c:356,215; sleep 4;  screencapture -o -x -R281,138,900,600 $D/macslim-en-scan.png
cliclick c:356,254; sleep 4;  screencapture -o -x -R281,138,900,600 $D/macslim-en-process.png
cliclick c:356,330; sleep 7;  screencapture -o -x -R281,138,900,600 $D/macslim-en-cache.png
cliclick c:356,368; sleep 13; screencapture -o -x -R281,138,900,600 $D/macslim-en-uninstall.png
defaults delete com.vgoapp.macslim AppleLanguages   # 记得还原
```

侧栏坐标（窗口在 281,138）：智能扫描 y=215 / 进程管理 y=254 / 应用程序 y=292 / 缓存清理 y=330 / 应用卸载 y=368，x=356。

**踩过的坑**：
- `osascript set frontmost` **经常失效**（终端会抢回焦点）→ 必须用 `open <app>` 走 LaunchServices 激活
- 窗口位置必须先用 osascript 归一化到 `{281,138}` 再算点击点。我曾按 `(270,135)` 算，**偏 11pt 导致所有点击落空**
- 应用卸载页首次加载要 **11 秒以上**（性能修复前的遗留），截图前 sleep 要够
- 抓拍前先确认视图对：搜索框会残留上次的过滤词，导致列表空白
- `cliclick` 的合成事件**无法**驱动 WKWebView 滚动条、滚动、以及 Tauri 原生窗口拖动

## 硬性约束（违反会出事）

1. **禁止 `git add` / `commit` / `stash` / `checkout`** — 用户多次明确指示。所有改动留在工作区
2. **禁止在 Rust 侧另抄英文译文** — 后端只发 key
3. **文案与 `code` 绝不参与安全判定** — 白名单、风险等级、selection key、TTL、单次消费、owner 绑定全部解耦
4. **`ProcessIdentity.name` 永远是原始进程名** — 不得放 i18n key 或错误码
5. **阶段名 i18n 不得给事件加字段** — `StageUpdate` 严格 4 字段，有门禁钉死
6. **`invoke_handler` 必须保持 16 条命令** — `scripts/operation_surface_checks.py` 钉死
7. **禁止 `git add .`**，逐文件 add（`AGENTS.md` §8）
8. 真实 Key ID / Issuer ID / 私钥路径**一律不进 git、不进文档**

## 血泪教训（新会话务必避免）

1. **brief 里给的示例代码必须由实现者实际编译运行验证**。本项目已三次踩坑：死锁的顺序断言、恒真的 `scan(None)` 等价断言、`.toBe` 过严断言
2. **复审结论进入决策前必须自行验证**。两次把复审者的机器观测结论直接写进裁决，结果前提是假的（`com.apple.dock.extra` 展示名、Safari vs Helper）
3. **性能只能用 release 构建测**。debug 下会得出「并行比串行慢 4 倍」的反向假象
4. **`test_updater_artifact.py` 的版本夹具已改为从 `tauri.conf.json` 读取**。曾因硬编码 `"0.2.2"` 导致改版本号时 18 个测试连锁失败；第一次「解耦成固定值」的修法也是错的（生产脚本会强制校验 archive 版本与配置一致）
5. **`bun run verify` 会被 `scripts/__pycache__` 拦下**。直接调 `python3 scripts/*.py` 会留下它；出现时 `rm -rf scripts/__pycache__` 即可（这个守卫工作正常，不是 bug）
6. **变异测试可能静默变成 no-op**。消息结构化后 `str.replace` 夹具失效，变异根本没发生——已被实现者发现并修
7. 源码层门禁**不能用「数量下限」代替「逐条集合比对」**（key 从抽取结果消失时下限照样满足）
